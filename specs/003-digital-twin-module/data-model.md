# Data Model: Digital Twin Module

This document defines the structure of the educational content for Module 2. As this is a documentation project, the "data model" refers to the organization of the content itself, not a database schema.

## Main Entities

### 1. Book Module

Represents the top-level container for the educational content.

- **Attributes**:
  - `title` (string): The main title of the module. e.g., "The Digital Twin".
  - `sectionName` (string): The name for the documentation section in Docusaurus. e.g., "Module 2: The Digital Twin (Gazebo & Unity)".

### 2. Chapter

Represents a single document or page within the Book Module.

- **Attributes**:
  - `chapterNumber` (integer): The sequential number of the chapter (1, 2, 3).
  - `title` (string): The title of the chapter.
  - `content` (Markdown/MDX): The body of the chapter, written in Docusaurus-compatible format.
  - `wordCount` (integer): The approximate number of words in the chapter.

### 3. Simulation Environment

Represents software platforms used for creating digital twins.

- **Attributes**:
  - `name` (string): Name of the environment (e.g., "Gazebo", "Unity").
  - `purpose` (string): Primary function of the environment in digital twin creation.

### 4. Sensor Model

Represents a type of sensor being simulated for robotic perception.

- **Attributes**:
  - `name` (string): Name of the sensor (e.g., "LiDAR", "Depth Camera", "IMU").
  - `dataOutput` (string): Type of data generated by the sensor.

## Relationships

- A `Book Module` contains one or more `Chapters`.
- Each `Chapter` belongs to exactly one `Book Module`.
- `Simulation Environments` are discussed within `Chapters`.
- `Sensor Models` are discussed within `Chapters`, often in the context of `Simulation Environments`.

## Validation Rules

- The `Book Module` MUST contain exactly 3 chapters.
- The `content` for each chapter MUST be in `.md` format.
- `Simulation Environments` and `Sensor Models` discussed MUST align with the module's focus.
